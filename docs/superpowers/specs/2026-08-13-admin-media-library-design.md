# Интуитивное управление фотографиями в админ-панели

## Цель

Заменить ручное редактирование путей и URL на понятную загрузку файлов с компьютера для автомобилей и локаций. Файлы не должны храниться на локальном диске приложения: постоянным хранилищем служит Supabase Storage.

## Пользовательский сценарий

### Автомобиль

- В разделе фотографий отображается заметная зона загрузки с кнопкой выбора файлов и поддержкой drag-and-drop.
- Можно выбрать несколько JPEG, PNG или WebP одновременно.
- Каждый файл загружается сразу после выбора и показывает собственный прогресс, состояние успеха или текст ошибки.
- Загруженные фотографии отображаются сеткой превью.
- Первое фото является обложкой. Пользователь может назначить другую обложку явной кнопкой.
- Порядок фотографий меняется перетаскиванием; клавиатурные кнопки перемещения обеспечивают доступную альтернативу.
- Для фотографии доступны действия «Скачать» и «Удалить». Удаление требует подтверждения.
- Технические URL и пути в интерфейсе не показываются.

### Локация

- Используется тот же загрузчик в режиме одного изображения.
- После выбора нового файла он сразу загружается и заменяет текущее изображение только после успешной загрузки.
- Доступны действия «Скачать», «Заменить» и «Удалить».

## Хранение и модель данных

- Создаётся закрытый bucket Supabase Storage `rpm-media`.
- Объекты автомобилей хранятся по пути `cars/<car-id>/<uuid>.<ext>`.
- Объекты локаций хранятся по пути `locations/<location-id>/<uuid>.<ext>`.
- В базе сохраняется стабильный storage path, а приложение формирует временный signed URL для отображения и скачивания.
- Существующие локальные пути, HTTPS URL и проксируемые ссылки Яндекс Диска продолжают отображаться, чтобы миграция интерфейса не ломала текущий каталог. Новые ссылки вручную добавлять нельзя.
- Для новых автомобилей временный ID создаётся до загрузки первого файла и затем используется при сохранении карточки.

## Компоненты и границы

- `AdminMediaUploader` — клиентский компонент выбора файлов, прогресса, превью, сортировки и удаления. Работает в режимах `multiple` и `single`.
- Серверные media actions/API — проверяют админ-сессию, тип, размер, назначение и идентификатор сущности; выдают разрешение на загрузку и выполняют удаление.
- Storage adapter — единственное место, которое знает bucket, правила путей и создание signed URL.
- Формы автомобиля и локации получают только нормализованное состояние медиа и передают его при обычном сохранении сущности.

## Поток данных

1. Пользователь выбирает или перетаскивает файл.
2. Клиент сразу проверяет расширение, MIME-тип и размер.
3. Сервер повторяет проверку и загружает файл в Supabase Storage.
4. После успеха клиент показывает превью и добавляет storage path в скрытое состояние формы.
5. Сохранение карточки фиксирует актуальный порядок изображений в базе.
6. Удаление уже сохранённого изображения удаляет связь из формы; объект удаляется из Storage после подтверждённого сохранения, чтобы отмена редактирования не теряла файл.
7. Неиспользованные новые загрузки очищаются по сроку жизни отдельной служебной процедурой; в рамках первой версии также удаляются при явной отмене или замене.

## Ограничения и безопасность

- Форматы: JPEG, PNG, WebP.
- Максимальный размер: 15 МБ на файл.
- Все операции требуют действующую админ-сессию.
- Имя исходного файла не используется как путь; применяется UUID и расширение из проверенного MIME-типа.
- Bucket закрыт от публичной записи и чтения.
- Ошибка одного файла не отменяет успешно загруженные файлы.
- Повторная отправка не создаёт дублирующую запись в карточке.

## Состояния интерфейса

- Пустое: пояснение форматов и размера, кнопка выбора, область перетаскивания.
- Загрузка: превью-заглушка, имя файла, процент, возможность отмены.
- Успех: превью и доступные действия.
- Ошибка: понятная причина и кнопка повторной попытки.
- Сохранение карточки: действия с порядком блокируются до ответа сервера.

## Проверка

- Модульные тесты нормализации путей, ограничений типа/размера и порядка изображений.
- Компонентные тесты выбора нескольких файлов, назначения обложки, сортировки, удаления и режима одного изображения.
- Интеграционные тесты отклонения неавторизованной загрузки и неверных файлов.
- Ручная проверка в production-подобном окружении: автомобиль и локация, desktop и mobile, загрузка, прогресс, сохранение, повторное открытие, скачивание и удаление.
- Проверка отсутствия ошибок Next.js overlay и релевантных ошибок консоли.

## Не входит в первую версию

- Добавление фотографий по URL.
- Редактирование и кадрирование изображений.
- Автоматическое сжатие оригиналов на сервере.
- Массовый перенос существующих фотографий Яндекс Диска в Supabase Storage.
