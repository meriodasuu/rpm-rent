# RPM Rent — аудит бизнес-логики и целостности домена

Дата проверки: 2026-08-09. Область: публичный каталог и заявка, API, FileStore, PostgreSQL/Prisma, админские действия, статусы, цены и исторические данные.

## Итог

Подтверждённые критичные обходы закрыты в коде. Создание заявки теперь проходит через единый доменный слой `prepareBooking`: он повторно проверяет доступность машины, календарный период, настроенность правил, возраст, стаж, услуги и деньги. FileStore выполняет всю операцию в последовательной очереди записи; PostgreSQL использует serializable-транзакцию и exclusion constraint по активным периодам.

Публичный релиз всё ещё заблокирован фактами владельца: у всех восьми текущих автомобилей отсутствуют минимальный возраст, минимальный стаж и минимальный срок. Система не подставляет значения и не принимает по таким машинам онлайн-заявки. Требования перечислены в `OWNER_RELEASE_INPUT.md`.

## Жизненный цикл заявки

| Текущий статус | Разрешённые следующие статусы | Блокирует даты |
|---|---|---|
| NEW | IN_PROGRESS, CONFIRMED, DECLINED, CANCELLED | да |
| IN_PROGRESS | CONFIRMED, DECLINED, CANCELLED | да |
| CONFIRMED | COMPLETED, CANCELLED | да |
| DECLINED | нет | нет |
| CANCELLED | нет | нет |
| COMPLETED | нет | нет |

Повторное сохранение того же статуса является безопасным no-op. Обратные переходы и повторное открытие финальной заявки дают 409.

## Денежная модель

- Все суммы хранятся целыми рублями; floating point в расчёте не используется.
- `rentalDays = endDate - startDate` в календарных сутках.
- `rentalPrice = rentalDays × pricePerDaySnapshot`.
- `additionalServicesPrice = сумма snapshot-цен выбранных услуг`.
- `dueWithoutDeposit = rentalPrice + additionalServicesPrice`.
- Залог не входит в `dueWithoutDeposit`.
- Отрицательные, дробные, `NaN`, небезопасные и превышающие технический денежный предел значения отклоняются, а не обнуляются.

## Защита административного контура

- Каждое изменяющее Server Action повторно вызывает `requireAdmin`; защита layout не считается достаточной.
- Сессия подписана HMAC, cookie `HttpOnly`, `SameSite=Lax`, `Secure` в production, TTL 10 часов.
- Вход ограничен по частоте, сравнение пароля выполняется и для неверного email.
- Slug автомобиля и услуги уникален в обоих хранилищах.
- Автомобиль с историей заявок удалить нельзя; штатная альтернатива — снять с публикации.
- Услугу, использованную в заявке, удалить нельзя; штатная альтернатива — снять с публикации.
- В админке доступны только разрешённые следующие статусы; сервер повторно проверяет переход.
- Произвольный `source` публичного запроса отклоняется; источник назначается сервером.

## Остаточные риски и обязательные действия владельца

1. **Release blocker:** заполнить возраст, стаж и минимальный срок для каждого автомобиля. Сейчас все восемь машин корректно fail closed.
2. **Release blocker:** утвердить юридическую политику, оператора данных, срок хранения, получателей (включая CRM) и окончательный текст consent.
3. **Release blocker:** применить миграцию `20260809000000_domain_integrity` к production PostgreSQL и прогнать race-test на реальной БД. В локальной среде `DATABASE_URL` отсутствует, поэтому миграция валидирована статически, но не развёрнута.
4. Для нескольких production-инстансов заменить in-memory rate limit публичной формы и входа на общий Redis/gateway limiter. Текущий лимит является базовой защитой одного процесса.
5. Владелец должен определить SLA, после которого необработанный NEW перестаёт блокировать календарь; автоматическое истечение не выдумывалось.
6. Владелец должен подтвердить, всегда ли заявитель является водителем, и правила второго водителя.
7. В локальной legacy-базе найдены три прошлые пересекающиеся заявки Porsche на 2026-08-08—2026-08-09 со статусами NEW/IN_PROGRESS и без новых eligibility snapshots. Они сохранены как история и явно помечаются в админке как legacy; владелец должен перевести их в фактические финальные статусы. Миграция не выдумывает исход и исключает старые строки из нового DB constraint, но application-check продолжает учитывать их.
